# 9 — Minimum validation experiment

Goal: produce the smallest amount of evidence that would justify (or refute) connecting a real visual
encoder, without overwriting existing artifacts and without claiming Gate E succeeded.

## 9.1 Prerequisites (fix first, in this order)

1. F6: retrain the evidence model on train+cal only; report the deployed model's dev number.
2. F7: select the Gate C threshold on tempered calibration posteriors.
3. F8: add dev risk at threshold to the Gate C pass rule.
4. F9: select the Gate B threshold on cal only.
5. F1: make the posterior order-invariant (or document that it is not).
6. F3: make duplicate influence saturate (or document that it does not).
7. F12: route DINOv2 features into `EvidenceBuilder`.
8. F11: save full episode artifacts for every policy.

Until 1–4 are done, no new number should be added to the README.

## 9.2 Design

- **Data:** 600 scenes generated by the existing simulator with the existing seeds (train 11, cal 23,
  dev 37, test 53), plus 200 real (or rendered-from-CAD) inspection images if available. If no real
  images exist, the experiment is synthetic-only and must be labelled as such.
- **Arms:** (A) synthetic features (current baseline), (B) DINOv2 features, (C) DINOv2 features +
  dependence correction disabled (ablation), (D) pooled baseline (existing `pooled` arm).
- **Policies:** falsification, EIG, confidence, fixed, random, oracle (oracle reported separately as a
  baseline, not a competitor).
- **Seeds:** at least 3 independent seeds per arm; report per-seed and pooled.
- **Splits:** train fit, cal calibration, dev selection, **test evaluation once**. No threshold tuning
  on dev or test.

## 9.3 Sample sizes

| Gate | Current N | Proposed N | Rationale |
|---|---:|---:|---|
| A | 120 dev | 240 dev + 240 test | Lower bound of Wilson interval below 0.80 at N = 120. |
| B | 30 dev | 60 dev + 60 test | IoU interval [0.627, 0.905] is too wide. |
| C | 120 dev | 240 dev + 240 test | Coverage and risk at a threshold need stable rates. |
| D | 18 episodes | 200 episodes | 2/18 is uninformative; need ≥ 20 discordant pairs. |
| E | 120 | 400 (MDD ≈ 3.1%) or 1000 (≈ 2.0%) | 5.7% MDD at N = 120 is too coarse. |

Total: ≈ 1,000–1,500 episodes for Gate E alone. This is the cost of a defensible comparison.

## 9.4 Metrics and reporting

- Accuracy with Wilson 95% intervals, per cause and for defect/reflection.
- ECE (equal-width and equal-frequency), Brier, NLL, with bootstrap intervals.
- Selective risk at 50% coverage and at the certified threshold; coverage at the threshold.
- Revision: conditional recovery rate **and** change in Brier score across the trajectory; number of
  discordant revisions.
- Planner: error rate, cost (calibrated), full action-sequence agreement, first-action distribution,
  with McNemar on discordant pairs.
- Dependence: order-invariance test (permute records, assert equal posterior), duplicate saturation
  test, `n_eff` vs a bootstrap estimate of the design effect.
- Integrity: `verify()` result, record count, model hash, checkpoint hash, seed list, git commit.

## 9.5 Pass criteria (all must hold)

1. Gate A: defect/reflection accuracy in [0.55, 0.80] on **test**, with lower bound ≥ 0.50.
2. Gate A: overall accuracy ≥ 0.80 on test, lower bound ≥ 0.75.
3. Gate B: pointing ≥ 0.95 and IoU ≥ 0.5 on ≥ 0.75 of test scenes.
4. Gate C: ECE ≤ 0.10 (equal-width, 15 bins), selective risk ≤ 0.20 at the certified coverage,
   coverage ≥ 0.40 on test.
5. Gate D: ledger arm Brier < pooled arm Brier by a margin whose 95% interval excludes zero.
6. Gate E: either a pre-registered non-inferiority margin is met, or the difference is reported as
   not established (no "equivalence" claim).
7. All artifacts reproducible from a single command with a manifest.

## 9.6 What would refute the approach

- Real-image per-cause accuracy outside [0.55, 0.80] (too easy or too hard).
- No detectable Brier improvement of the ledger over pooling at N = 200.
- Planner objectives remain indistinguishable at N = 1000.
- Temperature does not transfer to multi-look episodes.
- `n_eff` cannot be calibrated to match a bootstrap design effect.

Any one of these would be a legitimate negative result and should be reported as such, not buried.

## 9.7 Deliverable

A single `results/validation_report.json` containing: commit hash, model hashes, checkpoint hash, seed
list, per-gate numbers with intervals, pass/fail per criterion, and a one-paragraph verdict. No
figures are required for the minimum experiment; figures are for the paper.
